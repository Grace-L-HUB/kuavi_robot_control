## 第 2 页｜研究背景与意义

**标题**：为什么做这个项目？

**要点**
- 服务机器人需要**自然语言交互**，降低使用门槛
- 抓取任务需要**视觉定位**，将「说什么」与「抓什么」关联
- 边缘 AI 平台（昇腾 NPU）可在**端侧完成推理**，减轻上位机算力压力
- 轮臂机器人是**移动 + 操作**的典型平台，具有课程综合训练价值

**讲稿要点**：从「人机交互」→「感知理解」→「运动执行」三个层次引出系统必要性。

## 第 4 页｜系统总体架构

**标题**：三机协作架构

**图示**（建议做成横向流程图）：

```
上位机（采图+录音）  →  Atlas 200I（AI推理）  →  下位机（ROS抓取）
     instance/              grasp_target.json         机械臂+夹爪
```

**三节点职责**
- **上位机**：RGB-D 图像、相机内参、语音录音
- **Atlas 200I**：ASR + NLU + YOLO + 坐标解算
- **下位机 Kuavo**：IK 逆解、轨迹规划、夹爪控制

**讲稿要点**：Atlas **不依赖 ROS**，通过 JSON 与下位机解耦，便于独立开发与调试。

## 第 7 页｜端到端数据流

**标题**：从语音到抓取，数据怎么走？

**流程（建议用编号箭头图）**

1. 用户说「拿瓶子」→ 录音 `record5.m4a`
2. 同步采集 `color_image.png` + `depth_image.png` + 相机内参
3. Atlas 流水线：
   - 语音 → 文本「拿瓶子」
   - NLU → `{action: fetch, target: bottle}`
   - YOLO → 检测框 → 抓取像素 (178, 298)
   - 深度采样 → `camera_coord_m: [-0.213, 0.074, 0.582]`
4. 输出 `grasp_target.json` 到下位机
5. 机械臂 IK → 三段位姿 → 夹取 → 安全放开

**素材建议**：右侧放 `instance/grasp_target.json` 截图（关键字段高亮）

## 第 8 页｜语音交互模块

**标题**：听得懂——语音 ASR + 语义 NLU

**ASR 流程**
- 输入：m4a / wav 音频
- Whisper NPU encoder 加速 + CPU decoder
- 输出：中文文本

**NLU 能力**
- 动作识别：拿 / 取 / 抓 → `fetch`；停止 → `stop`
- 物体识别：瓶子、杯子、球、手机…
- 颜色属性：红、蓝、绿…（可选）
- 同音纠错：「屏子」→「瓶子」

**示例**
```
输入语音：「拿瓶子」
输出 JSON：{"action":"fetch", "target":"bottle", "attribute":null}
```

**讲稿要点**：规则 NLU 轻量可靠，后续可替换为大模型而不改上层接口。

---

## 第 9 页｜视觉感知模块

**标题**：看得见——YOLO 检测 + 三维定位

**检测**
- YOLOv8n NPU 推理，COCO 80 类
- 根据 NLU 的 `target` 筛选对应类别
- 抓取点：bbox 水平中心 + 垂直 65%（偏下，利于抓瓶身）

**定位**
- color 像素 → depth 像素映射
- 邻域中值采样深度 Z
- 内参反投影 → camera optical 三维坐标 (m)

**公式**（可放一页角标）
```
X = (u - cx) × Z / fx
Y = (v - cy) × Z / fy
```

**素材建议**：**必用** `instance/detection_result.png`（检测框效果图）  
旁侧可放 `instance/color_image.png` 原图对比

## 第 10 页｜机械臂控制模块

**标题**：抓得稳——运动规划与安全策略

**三段位姿接近**（默认路径）
1. 左上方就位（高 + 左 + 后，侧后方切入）
2. 平移至物品正上方
3. 垂直下降抓取

**安全放开流程**
- 夹紧 → 上提展示 → 下放 → **水平后撤** → 松爪 → 回零
- 避免原位松爪碰倒物体

**避障路径**（备选）
- 正上方 → 安全悬停（X 轴后撤）→ 纯垂直下降
- 防止末端执行器扫过物体

**讲稿要点**：路径规划考虑了 IK 收敛和碰撞安全，不是简单「直线下去抓」。

## 第 11 页｜关键创新与亮点

**标题**：本项目的 4 个亮点

1. **端侧 NPU 双模型推理**  
   Whisper + YOLO 均在 Atlas 上运行，无需 GPU 服务器

2. **模块解耦设计**  
   Atlas 输出标准 JSON，下位机脚本可独立部署调试

3. **多段安全抓取策略**  
   三段位姿 + 水平后撤松爪 + 双臂回零

4. **可配置参数体系**  
   脚本顶部「用户参数区」支持 `--dry-coords` 预览，便于现场调参

**讲稿要点**：创新不在「用了 YOLO」，而在「完整闭环 + 工程可落地」。

## 第 14 页｜开发难点与解决

**标题**：遇到的问题 & 解决方案

| 难点 | 解决方案 |
|------|----------|
| ONNX → OM 模型转换 | ATC 工具链，`soc_version=Ascend310B4` |
| Atlas `import acl` 失败 | 编写 `activate_kuavi_atlas.sh` 统一环境 |
| 正上方 IK 不收敛 | 拆分为「高位平移 + 下降」两段 |
| 抓取位置偏差 | `LEFT_GRASP_*_BIAS` 微调 + 重新采图 |
| 松爪碰倒物体 | 水平后撤后再松爪 |
| 语音识别同音错误 | NLU 同音纠错表（屏子→瓶子） |
| color/depth 时间不同步 | 强调同一次观测采集规范 |

**讲稿要点**：体现工程调试过程，比只讲成功更有说服力。

# 附录 C：一键生成 PPT 的快捷方式

1. 打开 PowerPoint → 选择「简洁科技」或「离子」主题  
2. 按本文 18 页顺序新建幻灯片，复制「标题 + 要点」  
3. 插入 → 图片：从 `instance/` 拖入检测图和场景图  
4. 插入 → SmartArt：把第 4、7 页流程做成流程图  
5. 幻灯片放映 → 排练计时，控制在 12 分钟内  

若使用 **Marp** / **Slidev**，可将每页 `---` 分隔转为 Markdown 幻灯片。
